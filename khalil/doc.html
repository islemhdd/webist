1. Contexte et Objectifs

1.1 Contexte

Dans le cadre d'un établissement de type académie militaire ou internat discipliné, il est nécessaire de gérer efficacement :

  • Les élèves répartis en sections hiérarchisées
  • Le suivi disciplinaire et sanitaire
  • Les autorisations de sortie
  • Les rapports d'incidents
  • La gestion des sanctions et récompenses

1.2 Objectifs Pédagogiques

  • Concevoir une application web fonctionnelle avec architecture MVC
  • Implémenter des opérations CRUD complètes sur 4 modules minimum
  • Manipuler une base de données relationnelle complexe
  • Gérer un système d'authentification avec rôles multiples
  • Produire des états de sortie pertinents et filtrés
  • Respecter les bonnes pratiques de développement web

2. Analyse des Besoins

2.1 Utilisateurs Cibles

Rôle Permissions Description
Administrateur Tous les droits Supervise tout le système, gère les utilisateurs
Officier Gestion élèves, sanctions, rapports Encadrant des sections, responsable disciplinaire
Médecin Consultation et validation dossiers médicaux Personnel médical de l'établissement
Élève Consultation personnelle, dépôt rapports Utilisateur de base, sujet aux sanctions et rapports

2.2 Besoins Fonctionnels

Module 1 : Gestion des Utilisateurs & Rôles (CRUD)

  • Créer: Ajouter des utilisateurs avec rôle spécifique
  • Lire: Consulter la liste des utilisateurs avec filtres par rôle
  • Modifier: Changer rôle, mot de passe, informations personnelles
  • Supprimer: Désactiver/archiver un compte utilisateur

Module 2 : Gestion des Élèves (CRUD)

  • Créer: Ajouter un élève avec matricule unique et attribution de section
  • Lire: Fiche complète élève + historique disciplinaire et médical
  • Modifier: Changer section, grade, statut (consigné/libre)
  • Supprimer: Archiver un élève (sortie définitive avec justification)

Module 3 : Gestion des Sanctions & Rapports (CRUD)

  • Créer: Enregistrer sanction ou rapport disciplinaire
  • Lire: Historique disciplinaire complet par élève
  • Modifier: Mettre à jour statut des rapports (en cours/traité/classé)
  • Supprimer: Supprimer des entrées erronées (avec log d'audit)

Module 4 : Gestion Médicale & Sorties (CRUD)

  • Créer: Dossier médical / demande de sortie avec justificatif
  • Lire: Consultation certificats médicaux / autorisations de sortie
  • Modifier: Valider/invalider certificats médicaux par le médecin
  • Supprimer: Nettoyer données médicales obsolètes (après expiration)

2.3 Besoins Non-Fonctionnels

Critère Exigence
Performance Temps de réponse < 2 secondes sur serveur local
Sécurité Authentification obligatoire, hashage mots de passe (bcrypt), protection CSRF
Fiabilité Sauvegarde automatique quotidienne des données

Utilisabilité Interface intuitive en français, responsive design

4.2 Fonctionnalités CRUD Obligatoires

CRUD 1 : Gestion Élèves

// Routes Laravel pour le module élèves Route::resource('students', StudentController::class); // GET /students → Liste paginée avec filtres // POST /students → Création nouvelle fiche // GET /students/{id} → Détails complets élève // PUT/PATCH /students/{id} → Modification fiche // DELETE /students/{id} → Suppression/archivage

CRUD 2 : Gestion Sanctions

  • Types de sanction prédéfinis avec durées associées
  • Historique visuel chronologique par élève
  • Export PDF des sanctions en cours
  • Alertes pour sanctions arrivant à expiration

CRUD 3 : Gestion Rapports

  • Dépôt de rapports par les officiers avec pièces jointes optionnelles
  • Workflow : création → validation → traitement → archivage
  • Recherche multicritères (élève, date, type, statut)
  • Notifications pour rapports nécessitant traitement

CRUD 4 : Gestion Médicale

  • Certificats médicaux avec dates de validité
  • Validation par le médecin avec signature électronique
  • Alertes automatiques pour certificats expirant dans 15 jours
  • Historique médical complet par élève

4.3 Système d'Authentification

  • Middleware auth sur toutes les routes protégées
  • Middleware role:admin,officer pour permissions granulaires
  • Sessions Laravel sécurisées avec chiffrement
  • Déconnexion automatique après 30 minutes d'inactivité
  • Journalisation des tentatives de connexion échouées

4.4 États de Sortie (Reports)

  1. Liste des élèves par section avec pagination et tri multiple
  2. Élèves actuellement consignés avec motifs et durées
  3. Sanctions en cours triées par gravité et date de fin
  4. Sorties autorisées cette semaine avec détails complets
  5. Statistiques générales (dashboard admin avec Chart.js)
  6. Rapport médical mensuel par section et par pathologie

6.3 Documentation

Guide d'installation :

1. Installer XAMPP (Apache + MySQL + PHP) 2. Cloner le dépôt Git : git clone [url-du-projet] 3. Naviguer dans le dossier : cd sgemm-project 4. Installer les dépendances : composer install 5. Copier le fichier .env : cp .env.example .env 6. Générer la clé d'application : php artisan key:generate 7. Configurer la base de données dans .env : DB_DATABASE=sgemm DB_USERNAME=root DB_PASSWORD= 8. Créer la base : php artisan migrate 9. Lancer les seeders : php artisan db:seed 10. Démarrer le serveur : php artisan serve 11. Accéder à l'application : http://localhost:8000

Comptes de test par défaut :

  • Administrateur : admin@esmm.local / password
  • Officier : officer@esmm.local / password
  • Médecin : doctor@esmm.local / password
